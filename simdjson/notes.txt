1. Why we do padded_string

The simdjson library achieves extreme speeds by using SIMD (Single Instruction, Multiple Data) instructions, which process multiple bytes of data simultaneously (e.g., 32 or 64 bytes at a time).

    The Safety Problem: To be fast, SIMD instructions often "over-read." They might read 32 bytes even if only 5 bytes are left in your JSON string.

    The Crash Risk: If your JSON string ends exactly at the boundary of a memory page and the CPU tries to read past it into "unallocated" memory, your program will crash with a Segmentation Fault.

    The Solution: padded_string ensures there are always extra null bytes at the end of the data, creating a "safety zone" for the SIMD hardware to read into without hitting protected memory.
